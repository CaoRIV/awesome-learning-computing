# Software Requirements & OOAD Knowledge Base

Knowledge base tiếng Việt để học có hệ thống:

> Software Requirements Engineering → Specification → Use Cases → Object-Oriented Analysis → UML → Object-Oriented Design → Implementation & Testing

Mục tiêu cuối cùng không phải là vẽ được nhiều diagram, mà là có thể giải thích và bảo vệ toàn bộ chuỗi quyết định:

```text
Business need
  → Software requirement
  → Acceptance criterion
  → Use case / scenario
  → Analysis model
  → Design model
  → Code
  → Test evidence
```

## Nguyên tắc học

1. **Understanding > Memorization** — giải thích được lý do trước khi nhớ thuật ngữ.
2. **Reasoning > UML Syntax** — diagram phải trả lời một câu hỏi phân tích hoặc thiết kế.
3. **Requirements > Diagrams** — không tạo model khi chưa biết requirement nào cần được làm rõ.
4. **Design Decisions > Drawing Diagrams** — mỗi quan hệ và abstraction phải có lý do.
5. **Practical Application > Definitions** — concept phải được dùng trong scenario, artifact hoặc code.

## Quy ước ngôn ngữ

- Giải thích bằng **tiếng Việt**.
- Giữ thuật ngữ English ở lần xuất hiện đầu tiên và khi cần tra cứu tài liệu kỹ thuật.
- Phân biệt rõ thuật ngữ chuẩn, convention phổ biến và lựa chọn phụ thuộc ngữ cảnh.
- Ví dụ phải chỉ rõ system boundary và assumption; không để người học suy luận từ bối cảnh ngầm.
